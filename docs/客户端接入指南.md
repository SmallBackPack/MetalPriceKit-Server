# 客户端接入指南

> 面向 Swift 客户端开发者。服务端已实现并通过测试，本文档描述客户端**必须怎么接**。
> 与客户端仓库里的 `Docs/服务端API设计.md`（业务契约）配套阅读：
> 那份文档说「返回什么」，这份说「怎么安全地拿到」。

---

## 一、接入顺序

```
1. GET  /v1/mpk-bootstrap        拿服务端公钥（明文，唯一一个明文接口）
2. 生成客户端 X25519 密钥对
3. 派生会话密钥（ECDH + HKDF）
4. 之后每次请求都带 X-MPK-CK: <客户端公钥 base64>
5. 业务接口的响应体是密文信封，按本文第五节解开
```

第 1 步的结果可以缓存（服务端公钥是长期不变的），建议缓存在 Keychain 或直接缓存到下次启动。

## 二、路径表

**对外路径是混淆过的随机串**，看不出接口用途。当前值（以 `config/routes.json` 为准）：

| 逻辑名 | 对外路径 | 方法 | 鉴权 | 说明 |
|---|---|---|---|---|
| bootstrap | `/v1/mpk-bootstrap` | GET | 否 | **明文**，只返回公钥 |
| quotes | `/v1/gpwwvvew-deevda` | GET | 否 | 行情快照（加密） |
| metals | `/v1/mkkzprqp-vvndte` | GET | 否 | 品种字典（加密） |
| fx | `/v1/tqzxvnrk-lzbor` | GET | 否 | 汇率表（加密） |
| config | `/v1/wqbdtoe-ocfvy` | GET | 否 | 结构化配置（加密） |
| fields | `/v1/rtkbmvxw-pflqs` | GET | 否 | **通用字段字典**（加密） |
| auth | `/v1/nrmlkzvc-xdpwo` | POST | 否 | 匿名身份（加密） |
| profile | `/v1/bhyftvzu-qmocn` | GET / PATCH | **是** | 用户资料（加密） |
| feedback | `/v1/oxrjqmie-vlwnk` | POST | **是** | 反馈（加密） |
| crash | `/v1/zeqmflkd-tvrnh` | POST | 否 | 崩溃上报（204，空 body） |
| events | `/v1/dfvbzckl-yrgmo` | POST | **是** | 埋点（204） |

> 轮换必须配合客户端发版，否则 App 全部 404。客户端**不要**把这些路径硬编码在多处，
> 集中放一个 `MKEndpoint` 枚举，改一处即可。

> ⚠️ **语义路径一律 404。** `/v1/quotes`、`/v1/metals` 这类名字服务端不存在，
> 连 401 都不会给（免得变成路径探测器）。契约文档里的路径只是逻辑名，不是真实路径。

## 三、通用约定

### 3.1 响应头

| 头 | 说明 |
|---|---|
| `X-Request-Id` | 请求追踪 ID，与服务端日志一一对应。用户报障时报这个号 |
| `X-MPK-Encrypted` | `1` = body 是密文信封；`0` = 明文 |
| `X-MPK-Kid` | 本次响应用的服务端密钥标识（客户端据此选公钥解密） |
| `ETag` | 强 ETag。带 `If-None-Match` 命中返回 304 空 body |
| `Cache-Control` | 按接口设定 |

### 3.2 状态码

| 码 | 含义 | 客户端处理 |
|---|---|---|
| 200 | 成功 | 解密 → 解析 |
| 201 | 已创建（反馈） | 解密 → 解析 |
| 204 | 已接收，无 body（崩溃/埋点） | 不解密 |
| 304 | ETag 命中 | **不解析 body**，沿用本地缓存 |
| 400 | 参数错误 / `client_key_required` / 信封解不开 | 错误态 |
| 401 | token 无效或过期 | 重新调 auth 换 token，**重试一次** |
| 404 | 路径不存在 | 错误态 |
| 429 | 限流 | 读 `Retry-After`，指数退避 |
| 500 | 服务端自身故障 | 错误态 + 重试按钮 |
| 503 | 还没有任何快照（刚启动） | 退避重试 |

错误响应体（未加密）形如 `{"error":"bad_request"}`。
**`error` 是字符串枚举，不是数字**，新增取值时客户端要按未知值兜底而不是崩溃。

> **上游行情源故障不是 5xx。** 走 `200` + `isStale: true`，
> 因为数据本身是好的，返回 5xx 会让所有用户看到红色错误页。5xx 只代表服务端自己的问题。

### 3.3 鉴权

| 接口组 | 是否需要 token |
|---|---|
| quotes / metals / fx / config / fields / bootstrap / crash | **不需要** |
| profile / feedback / events | **需要** `Authorization: Bearer <token>` |

token 是**归因 + 预留身份**，不是访问控制凭证 —— 客户端可以无限注册。
它解决的是「同一 WiFi 下多人不互相限流」和「反馈能关联到人」，不是「防伪造」。

> **崩溃上报是唯一的例外**，允许匿名 —— 崩溃时客户端可能还没拿到 token。

### 3.4 限流

| 维度 | 阈值 | 说明 |
|---|---|---|
| IP | 60 req/min | 服务端进程内计数 |
| token | 30 req/min | 只对带 token 的接口生效 |

429 的响应头有 `Retry-After`（秒），照着退避。

## 四、加密协议

### 4.1 为什么是这一套

- **X25519 ECDH**：服务端只有一把长期私钥，客户端不需要注册自己的密钥（省一轮接口）。
  ECDH 出来的共享密钥每个客户端都不同 —— 一个客户端的密钥泄露不会波及其它客户端。
- **HKDF-SHA256**：把 ECDH 的共享密钥变成用途分离的会话密钥。
- **AES-256-GCM**：自带认证标签，密文被篡改会**解密失败**，不会静默返回垃圾数据。

### 4.2 密钥协商（bootstrap，明文）

```http
GET /v1/mpk-bootstrap
```

```json
{
  "v": 1,
  "algorithm": "X25519-HKDF-SHA256-AES-256-GCM",
  "keys": [
    { "kid": "k1", "publicKey": "YWjm2iKp8+c0GyYob0NP6PZgnX0e+X4hQW4E/sMJ3H0=" }
  ]
}
```

`publicKey` 是 **raw 32 字节 X25519 公钥的 base64**（不是 DER，不是 PEM）。
这个接口必须明文 —— 客户端此时还没有密钥，解不开密文。
它只暴露公钥，泄露无害。

### 4.3 客户端密钥对

客户端**自己**生成 X25519 密钥对：

- **每次启动生成一把新的**即可（不需要持久化，也不需要注册）。
- 公钥放请求头 `X-MPK-CK`，base64 编码的 32 字节 raw 公钥。
- 私钥只留在内存里。

> 服务端的 `keys` 是一个数组（为密钥轮换预留），**当前只有一把在用**。
> 客户端**不要**假设 `keys[0]` 就是生效的那把 —— **以信封里的 `kid` 为准**：
>
> - **解密响应**：读 `envelope.kid`，从 bootstrap 的公钥表里挑 `kid` 相同的那把来派生密钥。
>   服务端加密时用的一定是生效的密钥，`kid` 会如实写在信封里，所以这样取一定对。
> - **加密请求**：从表里任选一把 `kid` 都可以 —— 服务端按**请求信封里的 `kid`** 去挑自己的私钥，
>   两边用同一把即可。推荐直接用响应里看到的那个 `kid`，少一层心智负担。

### 4.4 会话密钥派生（逐字节）

```
shared = X25519(serverPrivateKey, clientPublicKey)     // 32 字节
key    = HKDF-SHA256(
           ikm  = shared,
           salt = "metalpricekit/v1",                    // 固定常量，UTF-8
           info = "metalpricekit/v1/response",           // 响应方向
           len  = 32
         )
```

请求方向用 `"metalpricekit/v1/request"` 作为 info，**与响应方向不同**。
这样响应方向的密文不能拿去当请求方向用。

> salt 用固定常量而不是拼公钥，是为了让 Swift 侧少拼一段字节。
> 共享密钥本身已经每个客户端唯一，再拼公钥没有额外收益。

### 4.5 信封格式

加密后的响应体是一个 JSON 对象：

```json
{
  "v": 1,
  "kid": "k1",
  "c": "<base64>",
  "ts": 1793818620289
}
```

`c` 解 base64 后的字节布局：

```
┌────────────┬──────────────────┬────────────┐
│ nonce(12)  │  ciphertext(n)   │  tag(16)   │
└────────────┴──────────────────┴────────────┘
   GCM nonce     密文              认证标签
```

- nonce 是 12 字节随机数（GCM 标准长度），每次响应都不同。
- tag 是 GCM 的 16 字节认证标签，**不包含在密文里**，是独立的一段。
- `ts` 是服务端毫秒时间戳，供客户端做时钟校验与防重放参考。

### 4.6 AAD（附加认证数据）

```
AAD = "<METHOD>\n<PATH>\n<KID>"
```

- METHOD 大写（`GET` / `POST` / `PATCH`）
- PATH 是**真实请求路径**，不含查询串。例：`GET` + `/v1/gpwwvvew-deevda` + `k1`
- KID 是本次使用的密钥标识

AAD 的作用是把密文**绑死在「哪个接口」上**：把 `/v1/quotes` 的密文搬到 `/v1/fx` 去解，
认证标签校验会失败。客户端解密失败时先检查这一段。

### 4.7 请求体加密（可选）

POST / PATCH 的请求体**可以是明文 JSON，也可以是同样的信封格式**。
加密时用**请求方向**的密钥（info = `metalpricekit/v1/request`），
AAD 里的 METHOD 换成实际方法。

服务端按 body 里有没有 `v/kid/c` 三个字段自动判断是明文还是信封，两种都接受。

### 4.8 Swift 参考实现

```swift
import CryptoKit
import Foundation

/// 服务端约定的固定 salt，**不要改**。
enum MPKCrypto {
    static let salt = "metalpricekit/v1"

    enum Direction: String {
        case request
        case response
    }

    // MARK: - 密钥协商

    struct BootstrapKey: Decodable {
        let kid: String
        let publicKey: String   // base64 的 32 字节 raw 公钥
    }

    struct Bootstrap: Decodable {
        let v: Int
        let algorithm: String
        let keys: [BootstrapKey]
    }

    // MARK: - 客户端密钥对

    /// 每次启动生成一把新的即可，不需要持久化，也不需要向服务端注册。
    static func makeClientKeyPair() -> Curve25519.KeyAgreement.PrivateKey {
        Curve25519.KeyAgreement.PrivateKey()
    }

    /// 请求头用的 base64 公钥。
    static func headerValue(for keyPair: Curve25519.KeyAgreement.PrivateKey) -> String {
        keyPair.publicKey.rawRepresentation.base64EncodedString()
    }

    // MARK: - 会话密钥

    /// 与服务端 crypto.ts 完全一致：ECDH → HKDF-SHA256(salt 固定, info 分方向)。
    static func sessionKey(
        clientPrivate: Curve25519.KeyAgreement.PrivateKey,
        serverPublicBase64: String,
        direction: Direction
    ) throws -> SymmetricKey {
        guard let serverPublicRaw = Data(base64Encoded: serverPublicBase64) else {
            throw MPKError.badServerKey
        }
        let serverPublic = try Curve25519.KeyAgreement.PublicKey(rawRepresentation: serverPublicRaw)
        let shared = try clientPrivate.sharedSecretFromKeyAgreement(with: serverPublic)

        // ⚠️ salt 必须显式传。CryptoKit 默认会用 shared secret 的公开密钥当 salt，
        //    与服务端不一致 —— 不显式传就会解不开。
        return shared.hkdfDerivedSymmetricKey(
            using: SHA256.self,
            salt: Data(MPKCrypto.salt.utf8),
            sharedInfo: Data("\(MPKCrypto.salt)/\(direction.rawValue)".utf8),
            outputByteCount: 32
        )
    }

    // MARK: - 信封

    struct Envelope: Decodable {
        let v: Int
        let kid: String
        let c: String
        let ts: Int
    }

    /// AAD = "<METHOD>\n<PATH>\n<KID>"
    static func aad(method: String, path: String, kid: String) -> Data {
        Data("\(method.uppercased())\n\(path)\n\(kid)".utf8)
    }

    /// 解开信封。布局：nonce(12) || ciphertext || tag(16)。
    static func open(
        _ envelope: Envelope,
        key: SymmetricKey,
        method: String,
        path: String
    ) throws -> Data {
        guard let raw = Data(base64Encoded: envelope.c) else {
            throw MPKError.badEnvelope
        }
        guard raw.count >= 12 + 16 else {
            throw MPKError.badEnvelope
        }
        let nonce = raw.prefix(12)
        let tag = raw.suffix(16)
        let ciphertext = raw.dropFirst(12).dropLast(16)

        let box = try AES.GCM.SealedBox(
            nonce: AES.GCM.Nonce(data: nonce),
            ciphertext: ciphertext,
            tag: tag
        )
        // authenticating 必须与服务端算的 AAD 逐字节一致，否则标签校验失败。
        return try AES.GCM.open(
            box,
            using: key,
            authenticating: aad(method: method, path: path, kid: envelope.kid)
        )
    }

    enum MPKError: Error {
        case badServerKey
        case badEnvelope
        case unknownKid(String)
    }
}
```

用法：

```swift
// 1. 拿服务端公钥表
let boot = try await fetchBootstrap()

// 2. 客户端密钥对
let clientKp = MPKCrypto.makeClientKeyPair()

// 3. 请求 + 解密
var request = URLRequest(url: URL(string: "\(baseURL)\(MKEndpoint.quotes.path)")!)
request.setValue(MPKCrypto.headerValue(for: clientKp), forHTTPHeaderField: "X-MPK-CK")

let (data, response) = try await URLSession.shared.data(for: request)

// 4. 按头判断要不要解密
if response.value(forHTTPHeaderField: "X-MPK-Encrypted") == "1" {
    let envelope = try JSONDecoder().decode(MPKCrypto.Envelope.self, from: data)

    // ⚠️ 用信封里的 kid 去公钥表里挑，不要用 keys[0]。
    //    服务端加密时用的是生效密钥，kid 写在信封里，照着挑一定对。
    guard let serverKey = boot.keys.first(where: { $0.kid == envelope.kid }) else {
        throw MPKError.unknownKid(envelope.kid)
    }

    let sessionKey = try MPKCrypto.sessionKey(
        clientPrivate: clientKp,
        serverPublicBase64: serverKey.publicKey,
        direction: .response
    )

    let plaintext = try MPKCrypto.open(
        envelope,
        key: sessionKey,
        method: "GET",
        path: MKEndpoint.quotes.path      // 必须与服务端收到的路径逐字节一致
    )
    let quotes = try JSONDecoder().decode(MKQuotesPayload.self, from: plaintext)
}
```

> `path` 必须与服务端 `req.path` 完全一致 —— **不含查询串、不含 BaseURL**。
> 如果客户端以后给接口加查询参数，`req.path` 仍然不含查询串，所以传路径就行。

## 五、解密后的数据结构

**加密只发生在传输层。** 解开后的 JSON 与 `Docs/服务端API设计.md` 里的结构**逐字段一致**，
客户端的 `Decodable` 不需要为加密做任何改动。

### 5.1 quotes

```json
{
  "serverTime": "2026-11-04T19:27:42.479Z",
  "marketStatus": "open",
  "changeBasis": "prevClose",
  "quotes": [
    {
      "code": "XAU", "name": "黄金",
      "price": 4061.22, "change": 0, "changeRate": 0,
      "currency": "USD", "baseUnit": "oz", "scale": 2,
      "asOf": "2026-11-04T19:27:04.605Z", "isStale": false
    }
  ]
}
```

客户端必须遵守的几条：

| 规则 | 说明 |
|---|---|
| `price` 与 `baseUnit` **成对使用** | 不要假设 `XAU` 一定是 oz、`HG` 一定是 t，以接口下发的为准 |
| `changeRate` 是**原始小数** | `0.0123` = 1.23%。**不乘 100**、不是字符串，渲染时才乘 |
| `change` 的单位是 `baseUnit` | 铜的 `change` 是 USD/吨，不是 USD/磅 |
| `marketStatus` 可能是 `open` / `closed` | 契约里预留了 `pre` / `after`，服务端暂不下发；**未知值按 `open` 处理，不要崩** |
| `isStale` 是**逐条**的 | 不同品种交易时段不同，一个可能开一个休 |
| 缺某个品种就是缺了 | **不要**用 0 兜底，列表里少一条就少一条 |

> ⚠️ **接入前必须先修客户端的单位换算系数。**
>
> 契约文档 §2.4 已经标红：`MKMetalUnit.ouncesPerUnit` 的 `.ton` 目前用的是**美制短吨**
> （`gramsPerPound * 2000` = 29166.6667 盎司），而中文「吨」是**公吨**
> （1,000,000 g = **32150.7466 金衡盎司**），系数偏小 9.28%，
> 换算出的每盎司价格偏高 10.24%。
>
> 铜 14330 USD/t 现在会算出 0.32489，正确值是 0.29474。
>
> 修法：`case .ton: return 1000 * MKMetalUnit.kilogram.ouncesPerUnit`
>
> **这条不修，服务端给的数据再准，客户端显示的也是错的。**
> 服务端只发 USD 基准价 + `baseUnit`，单位换算全在客户端 —— 系数错了服务端救不了。

> `marketStatus` 的判定基于**伦敦本地时间**（金属现货的参照时区 LBMA）：
> 周六日休市，周五伦敦时间 23:00 收市，外加服务端配置里的节假日。
> **客户端只管显示，不用自己算。**

### 5.2 metals / fx / config

与契约完全一致：

- `metals`：`{ serverTime, metals: [{ code, name, baseUnit, scale, category, order }] }`
- `fx`：`{ serverTime, base: "USD", asOf, rates: { "CNY": 6.674, ... } }`
  语义是 **1 USD = rates[X] 个 X 币**。服务端只下发 USD 基准价，换算在客户端做，
  顺序固定「**先单位、后币种**」。
- `config`：`{ serverTime, configVersion, features, runtime, app, marketing }`

`runtime` 里有两个**含义不同**的间隔，务必分清：

| 字段 | 含义 | 当前值 |
|---|---|---|
| `pollIntervalSeconds` | **客户端轮询我们**的间隔建议 | 15 秒 |
| `upstreamRefreshSeconds` | **我们拉上游**的间隔 —— 数据本身多久更新一次 | 600 秒 |

`pollIntervalSeconds` 短不代表数据新 —— 数据的新鲜度看 `upstreamRefreshSeconds`
和每条报价的 `asOf`。UI 上要表达「数据更新于 X 分钟前」，别让用户以为是秒级实时。

### 5.3 通用字段接口（fields）

**这就是你要的「[key: Any] 通用字典」。** 解密后就是一个扁平的 JSON 对象：

```json
{
  "pollIntervalSeconds": 15,
  "staleAfterMinutes": 30,
  "features": { "showGuide": true, "guideVersion": 1, "enableConverter": true, "enableMetalDetail": true },
  "marketing": {
    "bannerText": "",
    "bannerUrl": "",
    "noticeTitle": "行情数据说明",
    "noticeContent": "本应用行情来自第三方数据源，可能存在延迟，仅供参考，不构成投资建议。"
  },
  "units": { "default": "base", "allowed": ["base", "oz", "g", "kg", "lb", "t"] },
  "currencies": { "default": "CNY", "allowed": ["CNY", "CNH", "USD", "EUR"] },
  "experimental": { "remoteFieldsEnabled": true }
}
```

约定：

- 顶层是对象，值可以是任意 JSON 值（字符串/数字/布尔/数组/嵌套对象/null）。
- **客户端必须忽略不认识的 key**（老版本遇到新字段不能崩）。
- 服务端不下发 `configVersion` 和下划线开头的 key（那是元信息）。
- 内容来自服务端的 `config/remote-config.json`，**改文件即生效，不用重启、不用发版**。
- 客户端用 `[String: Any]` 解码（Swift 侧就是 `JSONSerialization` 或 `Codable` + `AnyCodable`）。

> `config` 与 `fields` **并存**：契约里的 `/v1/config` 是写死的强类型结构，
> `fields` 是完全由数据决定的通用字典。加新配置项走 `fields`，不用改服务端代码。
>
> 两者**不是两份独立数据**：`config` 里的 `features` / `marketing` / `runtime.pollIntervalSeconds`
> 直接来自 `fields` 那份配置文件。客户端读哪边都行，值一致。

---

## 六、客户端必须遵守的硬规则

1. **不知道的字段一律忽略。** 服务端会加字段，客户端不能因此崩。
2. **`changeRate` 不乘 100。**
3. **`price` 和 `baseUnit` 成对用。**
4. **404 就是路径不对**（不是你拼错了参数）。语义路径服务端不存在。
5. **400 `client_key_required` = 你的 `X-MPK-CK` 头没发或格式不对。**
   服务端默认要求加密，不降级成明文（否则加密形同虚设）。
6. **解密失败先查 AAD**：`method`、`path`、`kid` 三段必须与服务端逐字节一致。
   尤其注意 `path` 不含查询串。
7. **上游故障不是错误态。** `200 + isStale: true` 是正常返回，走弱化显示，不要弹错误。
8. **401 重新换 token 重试一次**，不要无限重试。profile / feedback / events 都要 token。
9. **token 存 Keychain**，`deviceId` 用 `identifierForVendor`。
10. **崩溃上报必须吞掉所有错误**，上报失败不能影响 App。
11. **`marketStatus` 未知值按 `open` 处理**（契约预留了 `pre`/`after`，服务端还没下发）。
12. **单位换算先单位、后币种**，且 `.ton` 的系数要先修对（见 §5.1 的警告）。

## 七、自检工具

```bash
node scripts/smoke.ts https://你的域名
```

它做的事：bootstrap → 生成密钥对 → 派生密钥 → 请求 quotes/metals/fx/fields → 解密 → 打印。

  XAU  4061.22  0.00%
  ...

汇率：base=USD 币种数=155 CNY=6.673962192755667
自检通过：加解密链路正常。
