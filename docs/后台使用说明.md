# 运营后台使用说明

服务端自带一个极简后台，两个用途：

1. **看真实用户数** —— 匿名用户也能统计到装机基数、设备数、日活、版本与地区分布。
2. **改通用字段下发** —— 改 `config/remote-config.json` 的内容，不用 SSH 上服务器手改文件。

没有前端框架、没有构建步骤、没有数据库要额外装。页面是服务端直接拼出来的 HTML，
所有操作都是浏览器原生表单提交。

---

## 一、怎么访问

后台**只在本机监听**，远程访问走 SSH 隧道：

```bash
# 在你自己的电脑上执行
ssh -L 8787:127.0.0.1:8787 user@你的服务器
```

然后浏览器打开：

```
http://127.0.0.1:8787/admin
```

输入管理口令即可。

### 管理口令

由服务端环境变量 `MPK_ADMIN_TOKEN` 决定：

```bash
# 生成一条随机口令
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

写进 `/etc/metalpricekit-server.env`：

```bash
MPK_ADMIN_TOKEN=<你生成的随机串>
```

**没配这个变量，后台就是关闭的** —— `/admin` 一律返回 503，并在启动日志里喊一声。
这是故意的：「忘了关」比「忘了开」危险得多。

### 生产环境还要在 Nginx 里挡一道

`deploy/nginx.conf` 已经带了：

```nginx
location /admin {
    deny all;
    return 403;
}
```

双保险。服务端本来也只监听 `127.0.0.1`，但万一有人把 `HOST` 改成 `0.0.0.0`，
这一条还在，公网上依然访问不到后台。

## 二、看板

打开 `/admin/dashboard` 看到的是几个核心数字 + 几张分布表。

### 五个数字，含义完全不同

这是最容易被误读的地方。看板上每个数字下面都写明了口径，但这里再说一遍：

| 数字 | 口径 | 怎么来的 |
|---|---|---|
| **装机基数** | 累计注册过的装机数 | `COUNT(*) FROM users`。同一台机器装多少次都算一次 |
| **30 天活跃装机** | 近 30 天有访问的装机数 | `users.last_seen_at` 在 30 天内 |
| **设备数** | 物理上有多少台设备 | 按 `vendor_id`（IDFV）去重 |
| **今日活跃 (DAU)** | 今天有多少人用过 | `user_activity` 表当天行数 |
| **30 天活跃 (MAU)** | 近 30 天有多少**不同的人**用过 | `user_activity` 近 30 天去重用户数 |

**装机基数 ≠ 设备数**：同一个用户换手机 → 设备数 +1、装机基数不变；
同一个手机重装 App → 装机基数不变（Keychain 里的 UUID 还在）、设备数 +1（IDFV 变了）。

### 为什么要有 `user_activity` 这张表

`users.last_seen_at` 只记「最后一次在哪天」。光有它答不了「今天有多少人用过」——
一个用户上周装、周五打开一次，今天问「今天有几个人」，答不上来。
所以每次客户端调 `auth` 都会在 `user_activity` 里记一条「今天这个用户活跃过」，
一天多来几次也只占一行（同一天的行上累加次数）。

### 分布维度

App 版本、地区（客户端上报的 `locale`）、iOS 版本、设备型号。
每张表是「取值 / 装机数 / 占装机基数的百分比」。空值统一归到「未知」。

### 埋点不在这里

客户端侧的页面访问、功能点击这类埋点走第三方平台（友盟 / TalkData 等），
本后台不重复采集，也不做埋点分析。服务端的 `/events` 接口保留着，
但后台不对它做视图。

## 三、用户列表

`/admin/users`：

- 按昵称或用户 ID 搜索
- 分页（每页 50 条）
- 导出 CSV（带 UTF-8 BOM，Excel 直接打开不乱码）

用户 ID 形如 `u_f87fc42a`，昵称是服务端自动生成的（`用户 f87f`）。
客户端可以 `PATCH profile` 改昵称。

## 四、通用字段配置控制台

`/admin/config`。改这个文件 = 改客户端调 `fields` 接口拿到的字典。

### 怎么改

每行一个字段，三列：

| 列 | 说明 |
|---|---|
| **字段名** | 下划线开头的（`_comment` 之类）是元信息，不在控制台里改 |
| **类型** | `string` / `number` / `boolean` / `json` / `null` |
| **值** | 按类型填。`json` 类型填的是 JSON 文本 |
| **操作** | `保留` 或 `删除` |

改完点「保存全部修改」。或者在下面「新增字段」里加一个新字段。

**保存前会先校验**，有问题的会明确告诉你哪个字段错在哪。

### 下发预览

页面下方「下发预览」显示的就是客户端**实际收到的内容** ——
`configVersion` 和下划线开头的元信息不会下发。

### 版本号

服务端自动管理，每次保存 **+1**。客户端可以据此判断要不要刷新本地缓存。

### 历史备份与回滚

每次保存前自动把上一份备份到 `data/config-backups/`。
「历史备份」列表里可以点「回滚」。

> 回滚只恢复**内容**，版本号**继续往上走**。
> 原因：客户端只认「版本号变大」才刷新缓存，版本号一退，
> 已经升到新版本的客户端会认为本地缓存仍是最新的，于是永远拉不到回滚后的内容。

### 护栏：`pollIntervalSeconds` 不能小于 15 秒

这个值是「客户端多久来问我们一次」。所有客户端加起来就是我们的 QPS：
1000 个客户端按 15 秒轮询约 67 QPS，改成 1 秒就是 1000 QPS。

服务端的单 IP 限流是 60 次/分钟，客户端一旦密集轮询，同一个 WiFi 下的用户会互相误伤
（他们的请求来自同一个出口 IP）。所以低于下限直接拒绝保存 —— 这是护栏，不是建议。

低于 30 秒会给出警告但允许保存。

### 文件会被重写吗

会，但排版保持不变。服务端有一个固定的序列化规则（顶层字段两格缩进、
同类型标量挨在一起、只含标量的数组写在一行里），
所以在控制台改一个字段，版本库里的 diff **只有那一行 + 版本号那一行**。

## 五、安全设计

| 项 | 做法 |
|---|---|
| 访问范围 | 只监听 `127.0.0.1` + SSH 隧道；Nginx 再挡一道 `deny all` |
| 口令 | `MPK_ADMIN_TOKEN`，定长比较（不泄露长度） |
| 会话 | HttpOnly + SameSite=Strict + Path=/admin 的 cookie，有效期 7 天 |
| 会话存储 | 无状态（签发时间 + HMAC），不落库。改口令即让所有旧会话失效 |
| 口令爆破 | 只在**猜错**时计数（10 次/分钟/IP）。成功登录不计数 |
| CSRF | 页面表单带隐藏字段、JSON 接口带自定义请求头；cookie 是 SameSite=Strict 跨站压根不带 |
| 与客户端隔离 | 后台口令、后台会话与客户端的匿名 token **完全不是一个体系**，不共用任何存储 |
| 用户数据 | 客户端上报的 `deviceId` / `vendorId` 入库前都做 HMAC，**库里不留原始设备标识** |
| XSS | 页面里所有插值都转义（昵称是用户可控内容） |

### 设备标识哈希用的 pepper

`MPK_ID_PEPPER` 不设时，服务端会在数据目录生成一个随机 pepper 存到 `id-pepper` 文件。

- 多实例部署 → 所有实例必须用同一个 `MPK_ID_PEPPER`。
- 单实例 → 用默认生成的就够，但**那个文件必须跟数据库一起备份**。
- pepper 换了 → 所有设备标识的哈希全变 → 所有用户被当成新用户重新计数。

## 六、JSON 接口

后台页面用到的接口，需要带上会话 cookie：

| 路径 | 说明 |
|---|---|
| `GET /admin/api/stats` | 全部统计（指标 + 日活序列 + 分布） |
| `GET /admin/api/users?q=&limit=&offset=` | 用户列表 |
| `GET /admin/api/users.csv?q=` | CSV 导出 |
| `GET /admin/api/config` | 当前配置（原始值 + 下发预览 + 备份列表） |
| `GET /admin/api/stats` 之外的状态改接口 | `POST /admin/config/save`、`POST /admin/config/restore`，需要 `X-MPK-CSRF` 头，值为会话 cookie 值 |

未登录时页面跳 `/admin/login`，接口返回 401。

## 七、常见问题

**后台打不开，显示「后台未启用」**
→ 没配 `MPK_ADMIN_TOKEN`。配好 restart。

**后台打不开，连接被拒**
→ 服务只监听本机。要么用 SSH 隧道，要么（不建议）改 `HOST`。

**配置改完客户端没拿到新值**
→ 改的是 `config/remote-config.json` 吗？`MPK_REMOTE_CONFIG_FILE` 可以把它指到别处。
另外确认改的字段没以 `_` 开头（下划线开头的不下发）。

**客户端拿到 400 `client_key_required`**
→ 这是加密要求，跟后台无关。生产模式强制加密，客户端必须带自己的公钥头。

**统计里的数字比预期少**
→ 确认客户端调了 `auth` 接口。DAU 只在调 `auth` 时记录，行情接口不记活跃。
